# カレンダー出力の設計と利用案内

## 出力範囲

生成結果と名前付き保存プランは、表示に使っている同じスナップショットから、選択した1案だけをICSへ出力する。標準では鑑賞する上映（上映前後イベントを含む）と食事を出力し、未鑑賞作品は含めない。現行モデルの昼食に加え、夕食機能導入後の `meals` スナップショットでは昼食・夕食を区別して出力する。「移動・入退場も追加」を選んだ場合だけ、それらを独立した予定として追加する。各上映だけの出力も可能である。

上映の説明にはイベント注記、データ上の時刻注記、設定した入退場バッファ、作品公式URLを含める。会場は名称と住所を含む。入退場バッファは上映予定自体の開始・終了には加えず、独立予定を選択した場合に出力する。

## ICS形式と識別子

`src/calendar/ics.ts` はUIから独立した純粋な生成処理であり、RFC 5545の `VERSION`、`PRODID`、`UID`、`DTSTAMP`、`DTSTART`、`DTEND` を出力する。日時はUTCのZ形式、改行はCRLF、TEXT値はバックスラッシュ・改行・カンマ・セミコロンをエスケープし、content lineはUTF-8で75オクテット以内に折り返す。

上映UIDは映画祭IDと上映IDから決まり、再生成しても変化しない。食事UIDは映画祭ID、プランID（未保存プランは上映ID列から決定的に算出）、日付、種別、開始時刻から決まる。再取り込み時に重複を避ける最終判断は受け取り側のカレンダーに依存する。

## 共有・保存と制限

「カレンダーに追加」はユーザー操作内で `navigator.canShare({files})` を確認し、対応時だけ `navigator.share({files})` を呼ぶ。共有成功は登録完了とは表示しない。キャンセルはエラーにせず、非対応または共有失敗時はICSをダウンロードして取り込み手順を表示する。生成したObject URLはクリック後に解放する。

共有先はOS依存であり、特定カレンダーアプリの起動や一括登録は保証しない。Google Calendarの公式ICS取り込みはPC版設定から行う。iPhone/iPadで直接共有できない構成では、保存したICSを「ファイル」から開いて対応カレンダーへ渡す。

## 実機確認

自動テストではWeb Share対応・非対応・失敗・キャンセルとダウンロードを確認する。リリース前に次の組み合わせで、共有メニューの表示だけでなくカレンダー側の取り込み確認画面まで到達することを手動確認する。

- iPhone Safari → Appleカレンダー（直接共有できない場合は「ファイル」保存経由）
- Android Chrome → 端末で利用可能なカレンダー
- PC → 保存したICSを対応カレンダーへインポート

確認時はOS、ブラウザ、カレンダーアプリの版と、直接共有／保存経由のどちらが利用できたかをリリース記録へ残す。サーバー連携、OAuth、ネイティブアプリ、webcal購読、自動同期は対象外である。
