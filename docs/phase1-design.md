# Phase 1: Scheduler Core 設計

## 範囲

SPEC.md §19 の Phase 1 を実装する。UI、実TIFFデータ、Pagesデプロイは Phase 2〜4。
将来のUIから使える、外部通信・React・DOM・Node APIに依存しないTypeScriptモジュールとする。
昼食制約と最大3案の結果構造もコアの実行可能性・最適化に必要なため実装する。

## APIと責務

`optimizeSchedule(input: ScheduleInput, maxPlans = 3): ScheduleResult`

- `types.ts`: SPECのエンティティ、入力・結果型、既定条件。
- `time.ts`: 分単位の絶対時刻、日本時間の日付、半開区間の重複。
- `validation.ts`: ID一意性・参照整合性・日時・非負整数・勤務/昼食時間帯の検証。
- `constraints.ts`: 必須滞在、移動、勤務、昼食。
- `scoring.ts`: 休暇日付・鑑賞日付の重複除去、移動/待ち時間、辞書式比較。
- `optimizer.ts`: 候補の少ない作品からDFS、スキップ分岐、Branch and Bound、上位k件保持。
- `index.ts`: 公開API。

入力は変更しない。結果の上映オブジェクトは入力を参照するため、呼び出し側はデータを読み取り専用として扱う。
空選択は空のplans。非空選択で有効上映がない場合は、全作品をmissedFilmIdsに含む空プランを返す。
不正データは例外にし、鑑賞不可能な有効データと区別する。
`visitedNodes` は性能計測用。時間切れで打ち切らず、返却結果は入力に対する厳密な上位k件。

## 未決事項に対するPhase 1の決定

| 項目 | 決定 |
| --- | --- |
| タイムゾーン | 常にAsia/Tokyo相当のUTC+09:00。端末のTZに依存しない |
| 入力日時 | ISO 8601の秒00・オフセット必須。Zも受け付け、日本時間へ正規化 |
| 日跨ぎ | バッファ・イベント込みの滞在が日本時間で同日であること。日跨ぎは明示的に拒否 |
| 勤務 | 初期9:00〜18:00、workStart/workEndで変更可能。曜日は日曜0〜土曜6 |
| 休暇 | 必須滞在と勤務時間が重なる勤務日を1日と数える。半休なし |
| 休日 | 通常休日・additionalDaysOffは休暇不要。設定した勤務曜日はholidaysより優先 |
| 祝日データ | コアには内蔵しない。holidaysは必須入力として検証するが、勤務曜日の判定を上書きしない |
| 休暇不可日 | 勤務日の勤務時間との衝突だけを禁止。夜間や元々休日の場合は参加可能 |
| イベント | 前後イベントは必須滞在。入場は前イベント開始前、退場は後イベント終了後 |
| 同一会場 | 明示的な対角移動時間があれば使用。未設定なら移動0分＋入退場バッファ |
| 異会場 | 有向マトリクス。逆方向を推測しない。欠損経路では連続鑑賞不可 |
| 別日 | 会場間移動は評価しない。自宅等からの往復・通勤時間は対象外 |
| 昼食 | 必須滞在が昼食時間帯に重なる日に必須。11:30〜14:30内に連続45分 |
| 昼食配置 | 上映間の移動を退場直後に置き、最も早い実行可能な空きに予約。最初/最後の上映の前後も利用可能 |
| 待ち時間 | 同日の連続上映間からイベント・入退場・移動・予約昼食を除いた時間。初回前/最終回後は不算入 |
| 同点 | 時刻順上映ID列のコードポイント順で安定化。多様性の追加評価は将来対応 |

映画の本編長とscreening.endAt-startAtの一致は強制せず、上映回の日時を正とする。
勤務時間と移動のみの重なりは休暇判定に含めない。通勤・会場移動中の勤務不可を扱う拡張時は別途仕様化する。
昼食は任意会場で確保可能と仮定し、飲食店への追加移動は含めない。
公開補助関数 `lunchBreaks` / `scorePlan` は日時順で実行可能な上映列を前提とする。

## 探索と安全な枝刈り

1. 入力全体を検証。休暇不可日に勤務と重なる上映候補を除外。
2. 候補数昇順、作品ID順で作品を並べる。
3. 各作品について各上映候補を選ぶ分岐と、作品を外す分岐を作る。
4. 途中では必須滞在の時間重複を枝刈りする。
5. k件揃った後、未鑑賞数の下界がk位より悪ければ枝刈り。同値なら既に確定した休暇日数でも枝刈り。
6. 葉で隣接上映の移動と昼食の実現可能性を判定する。
7. 未鑑賞数→休暇→鑑賞日数→移動→待ち時間→ID列でソートしてk件保持する。

任意の有向移動時間表では、途中に別上映を挿入することで隣接経路が変わる。
そのため、部分解での移動不可や昼食不可を無条件に枝刈りしない。
移動時間や待ち時間も部分解から単調増加するとは限らないので枝刈りに使わない。
上位3件を保持するため、同点を刈り捨てず、1位だけを基準に枝刈りしない。

最悪計算量は作品iの候補数をciとして O(∏(ci+1)) の組合せ探索（各節点の整列・検証コストが加わる）。
大規模データの実用性能は未保証。Phase 3で実データを測定し、必要ならPhase 5のWorkerや探索改善を導入する。

## 検証

`npm test` はNode 24の標準テストランナーでTypeScriptを直接実行。
`npm run typecheck` はstrict TypeScript検査、`npm run build` はJSと型宣言を生成。

12テストケースで衝突、境界時刻、非対称/欠損移動、イベント、JST、勤務・休日、休暇不可、昼食、休暇重複排除、辞書式比較、最大鑑賞数、不正入力を確認。
固定seedの40データセットについて、枝刈りなし列挙と厳密な上位3案を比較する。
列挙オラクルは制約/スコアを共有するため、制約自体は別の境界値テストで検証する。
欠損した直接経路が中間上映により成立するケースも回帰テストする。
