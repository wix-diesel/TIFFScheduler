# 日付別午後休と0.5日単位の最適化

## 入力

`UserConstraints` に次を追加する。

- `afternoonLeaveDates: string[]`: その日は午後休だけ取得可能
- `afternoonLeaveStart: string`: 午後休の共通開始時刻。初期値は `13:00`

午後休開始時刻は `workStart < afternoonLeaveStart < workEnd` を検証する。午後休指定日と追加休日・休暇取得不可日の重複も入力エラーにする。非勤務曜日と追加休日は従来どおり休暇不要で、午後休指定は適用しない。

## 行程の勤務判定

上映の占有枠に加えて、同日の会場間移動と予約した昼食を行程区間として判定する。職場・自宅から最初の会場までの移動と最後の帰路はモデル化しない。

- 通常勤務日: 勤務時間に重なれば `full / units=2`
- 午後休指定日: 午前勤務に重なる区間は候補外、午後勤務に重なれば `afternoon / units=1`
- 非勤務曜日・追加休日: `0`
- 休暇取得不可日に休暇が必要な区間がある場合: 候補外

同じ日で複数区間がある場合は必要量の大きい方を採用するため、午後休の区間が複数あっても1単位だけになる。最終行程で日別内訳を確定し、`vacationUnits` の合計をスコアに使う。表示上は `vacationUnits / 2` 日とする。

## 探索と昼食

上映占有だけから算出した休暇量を下界として枝刈りする。移動と昼食の配置は探索途中で変わるため、枝刈りの根拠には含めない。最終行程では移動・昼食を含めて再検証する。

昼食が必要な日は、昼食時間帯内の上映・入退場・移動の隙間から候補を作る。午後休指定日では午後休開始後の候補も試し、午前勤務と重ならない配置を優先する。候補がなければその上映組み合わせは不採用とする。

## スコア

比較順は次のとおり。

1. 未鑑賞作品数
2. 必要休暇量（`vacationUnits`）
3. 鑑賞日数
4. 移動時間
5. 待ち時間

したがって、同じ鑑賞数なら午後休1回は終日休暇1回より優先され、午後休2回と終日休暇1回は同じ休暇量として次の項目で比較される。
