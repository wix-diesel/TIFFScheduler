# Issue #11: 上映終了時刻の上限

## 仕様

`UserConstraints.latestScreeningEnd` は全日共通の任意制約とする。未指定は制限なし、指定値は日本時間の `HH:mm` として扱う。

各上映は、広告上の終了時刻 `endAt` に `eventAfterMinutes` を一度だけ足した時刻を、広告上の上映開始日の指定時刻と比較する。境界一致は許可する。`exitBufferMinutes` はこの比較には含めず、従来どおり上映間の移動、勤務、昼食の占有判定にだけ使用する。

比較基準を上映開始日に固定するため、翌日終了の上映は終了時刻の時刻部分が上限より早くても許可しない。これは帰宅時刻の条件ではなく、自宅への移動は計算しない。

開始下限と終了上限を両方指定した場合は、日付をまたがない時間帯として開始下限が終了上限より前でなければならない。

## 探索

`meetsLatestScreeningEnd` は副作用のない候補判定である。最適化処理は作品ごとの候補一覧を作る時点で条件外の上映を除外する。上映を選ぶ組み合わせに依存しない制約なので、候補生成時の除外によって実行可能解を失わない。

条件を満たす上映がない作品にも従来の未鑑賞分岐を残すため、全作品を鑑賞できない場合は最大鑑賞数の代替案を最大3件返す。未指定時はすべての候補を許可し、既存動作を維持する。

## UI・保存・互換性

開始下限と終了上限は同じ「上映時間帯」欄に任意の時刻入力として表示する。開始は上映前イベント、終了は上映後イベントを含めて判定する一方、入退場の余裕と帰路は含めないことを明示する。

任意項目は既存の自動保存対象であり、現在条件と名前付きプランのスナップショットへ保存する。schemaVersionは1を維持し、既存データに項目がなければ未指定へ移行する。

## 検証

- 22:00との境界一致と22:01の除外
- 上映後イベントで22:00および22:01になる境界
- 退場バッファによる22:00超過を許可
- UTC表記を含む日本時間比較
- 翌日01:00終了の除外
- 未指定、不正な時刻、開始下限との一致・逆転の拒否
- ブラウザ入力の自動保存・復元
