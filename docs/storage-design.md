# Issue #8: 設定とスケジュールの永続化

## 構成

- `src/storage/codec.ts`: 型定義、JSONの構造・スナップショット検証、fingerprint。
- `migration.ts`: 未設定の条件へ初期値を適用。条件追加時はここに移行を追加する。互換性を壊す変更ではスキーマ版を上げ、旧版からの明示的移行を実装する。
- `repository.ts`: localStorage取得・読み書き、元データの保護、他タブとの競合検知。
- `usePersistedSchedule.ts`: 最初のrender前に復元。初期状態の書き戻しを避け、ユーザー変更後に保存する。
- `SavedPlans.tsx` / `PlanView.tsx`: 一覧操作とスナップショットからのタイムライン表示。

## 保存形式

キーは `tiff-scheduler:tiff-2025`（映画祭IDと年度）。schemaVersion=1、festivalId、dataFingerprint、updatedAt、selectedFilmIds、constraints、lastResult、savedPlansを保持する。

lastResultは最大3案と入力全体。savedPlansは最大20件で、各プランにUUID、名前（1〜100文字）、保存日時、生成時fingerprintと入力・結果の独立コピーを保持する。入力には作品・上映・会場・移動時間・休日・鑑賞条件、結果には昼食・休暇日付・スコアを含む。保存データのタイトルを含め、Reactの通常のテキスト描画を利用する。

fingerprintは作品、上映、会場、移動、休日の全体JSONに対する長さと2種類の32bitハッシュ。セキュリティ用途ではなく配布データの変更検知に使用する。変更時は消滅IDを選択から除外し通知、現在結果をクリア。名前付きプランは書き換えない。

## エラーと競合

localStorageプロパティ取得から例外処理する。JSON解析、ネストした入力・結果の検証に失敗した場合と将来版の場合は書き込みを禁止し、元の値を保護する。容量超過・一時的な書き込み失敗は画面へ通知し、次の変更で再試行する。入力途中の不整合な昼食時間帯も保存可能だが、非有限数などJSONで安全に往復できない値は保存失敗として扱う。

保存前に読み込んだ値と現在の値を照合し、別タブによる変更を検出したら保存停止。storageイベント（全消去を含む）でも停止する。編集中の状態は維持し、再読み込み時のみ外部の変更を採用する。localStorageにはトランザクションがないため完全に同時の書き込みの排他保証はない。

任意項目 `maxScreeningsPerDay` は未指定を「制限なし」として扱うため、Issue #9より前のschemaVersion=1データもそのまま読み込める。指定値は1以上の整数だけを受け入れ、現在条件と保存プランのスナップショットの双方に保持する。

設定初期化は選択・条件・現在結果だけ、全削除は確認後に保存プランだけを変更する。未知版や破損データ保護中でもメモリ上では利用可能。自動的な元データ消去はしない。

ICSはカレンダー連携機能で追加する。保存スナップショットを共通の入力として渡せるため、上映データ更新後も保存時の時刻で出力できる。

## レビュー反映

復元時の上映照合はIDからシリアライズ済み上映へのMapを一度構築し、各上映を照合する。保存時はJSONのシリアライズと非有限数・件数上限の軽量検証だけを行い、JSONの再解析とスナップショットの完全検証は復元時に限定する。

全削除確認にはネイティブdialogのshowModalを使用し、背景を操作不可にする。説明文をaria-describedbyで関連付け、キャンセルへ初期フォーカスを移す。Escapeでも閉じ、閉じた後は起点ボタンへ戻す（全削除でボタンがなくなった場合は一覧見出しへ移す）。
