# Issue #10: 上映開始時刻の下限

## 仕様

`UserConstraints.earliestScreeningStart` は全日共通の任意制約とする。未指定は制限なし、指定値は日本時間の `HH:mm` として扱う。

各上映は、広告上の開始時刻 `startAt` から `eventBeforeMinutes` を一度だけ引いた時刻を、広告上の上映開始日の指定時刻と比較する。境界一致は許可する。`arrivalBufferMinutes` はこの比較には含めず、従来どおり上映間の移動、勤務、昼食の占有判定にだけ使用する。

開始下限と終了上限を両方指定した場合は、日付をまたがない時間帯として開始下限が終了上限より前でなければならない。Issue #10ではこの相互検証に必要な `latestScreeningEnd` の型と初期値を共有モデルへ用意するが、終了上限による候補除外とUIはIssue #11で実装する。

## 探索

`meetsEarliestScreeningStart` は副作用のない候補判定である。最適化処理は作品ごとの候補一覧を作る時点で条件外の上映を除外する。上映を選ぶ組み合わせに依存しない制約なので、候補生成時の除外によって実行可能解を失わない。

条件を満たす上映がない作品にも従来の未鑑賞分岐を残すため、全作品を鑑賞できない場合は最大鑑賞数の代替案を最大3件返す。未指定時はすべての候補を許可し、既存動作を維持する。

## UI・保存・互換性

条件欄の時刻入力は空欄を制限なしとして扱い、上映前イベントを含むことと入場バッファを含まないことを説明する。設定変更時は現在の生成結果をクリアする。

任意項目は既存の自動保存対象であり、現在条件と名前付きプランのスナップショットへ保存する。schemaVersionは1を維持し、既存データに項目がなければ未指定へ移行する。

## 検証

- 10:00との境界一致と09:59の除外
- 上映前イベントの開始が10:00および09:59になる境界
- 入場バッファによる09:50からの占有を許可
- UTC表記を含む日本時間比較
- 未指定、不正な時刻、終了上限との一致・逆転の拒否
- ブラウザ入力の自動保存・復元
